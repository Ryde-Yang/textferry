# 0.9.0：首次引导与成品收纳

转换请求先解释基础转换和 AI 整理校正的核查范围，等用户选择，再询问格式并推荐 Markdown。整理档还在开工前说明并询问是否显示来源页码；EPUB 对应来源章节标记。已明确的选择不重复询问，追加格式沿用原选择。只安装任务可以先安装、自检，Word 与 EPUB 组件按实际需求准备。

## 用户成果

新任务工作数据收在成果文件夹的 `.textferry/`；`deliver` 生成中文命名的成品，返回可点击路径。AI 整理档主要为所选格式整理稿、机器底稿和整理说明；基础 Markdown 复用底稿，不再复制相同内容。移动整个成果文件夹可保留来源与插图链接。

交付文件与内部工作稿分别保护。用户改过的交付稿会阻止静默重导出；需要继续时由 Agent 将修订对应到页稿、复核，并保留用户修订原件。

## 空间与恢复

新 PDF 任务保留一份必要的来源；选页只保留摘页与原页号对应。`--keep-original` 可额外保留整本，旧任务已有的完整来源不迁移删除。

`compact` 先预览，`--apply` 执行。只清理已完成任务的分批 / 上传 PDF 及可重建页图；清理前将页图核查哈希与不可变来源绑定。`page-image` 按需恢复校核图，来源变化仍会使核查失效。全文、正文插图、核查和远程受理记录保留，追加 Word 继续复用文字。

## 配置与进度

`setup` 返回是否已配置、实际生效来源和执行环境配置目录，不返回密钥。状态诊断无需读取凭证正文。`status` 提供简短完成数和待处理阶段，供 Agent 使用实际进度说明等待原因。`deliver` 直接生成可点击链接回执，按真实整理范围说明覆盖数；带公式或特殊符号的核查说明可通过 `--note-file` 读取 UTF-8 文件。

## 验证和边界

完整程序回归 200 项通过，无跳过；5 条现有 PyMuPDF SWIG 弃用提示。源码包独立安装后，PDF / EPUB × 基础 / 整理 × Markdown / Word 八种组合及清理后追加格式通过，运行期间禁止网络和读取开发代码。

真实宿主试用使用 Pi / Flash 和两页自制扫描材料；与程序回归、自制材料保全及专家校核是不同验证层次。最新事实与限制见 [验证记录](verification.md)。其他宿主的真实对话、Windows / Linux 和全部材料版式尚未逐一验收。
