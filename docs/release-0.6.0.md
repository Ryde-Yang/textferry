# 0.6.0 修复与 EPUB 支持

本次以首次使用、原始内容保全、恢复任务和交付为范围，使用自制材料验证。未重新处理真实书籍，未调用收费 OCR，未发布到 GitHub。

## 五项修复

| 审核发现 | 当前行为 | 验证依据 |
|---|---|---|
| 扫描正文有较长文字页脚时误判为可直接提取 | 大面积扫描图保守走 OCR，不以页脚字数认定正文完整；可能增加含大图页面的识别量 | `tests/test_release_fixes.py` 混合 PDF 样本 |
| 基础 Markdown 直接编辑后被 report / resume 覆盖 | 用生成哈希识别直接修改，保留文件并报告；不会将原文字重导出为已包含用户修改的 Word | 底稿编辑与 Word 保留回归 |
| OCR 返回的 HTML 表格在 Word 中变成标签文字 | 解析成真正表格，表格中的图片仍受本地资源检查；无法解析时明确报错 | Word 文档结构验证 |
| 共享文本保留图片引用却没有图片文件 | 目录当前限定纯文字；准备贡献或读取旧条目时拒绝图片 / 媒体引用，本地成果仍保留 | 贡献与旧目录下载回归 |
| OCR 任务受理编号没有持久化，恢复可能重复提交 | 提交前记录状态，受理后立即保存回执；超时、下载失败、中断后查询原任务，结果已到本机则复用；受理结果不明时停止自动重交 | 模拟远程服务验证提交仅一次；恢复时变更批大小仍使用原回执 |

最后一项不构成服务端“绝对只计费一次”的保证：无法控制服务计费，也无法在服务没有幂等凭证时自动判定所有断网时刻。因此，不明受理状态会暂停并要求先核对服务端，不冒险再次提交。

## EPUB

新增 `epub` 可选组件，无保护文字 EPUB 在本机按章节顺序提取；不需要百度令牌。支持基础转换 / AI 整理校正和 Markdown / Word，保留原文件、图片、可解析的表格 / 公式、章节定位及语义脚注。跨章脚注和章节链接有回归检查。

EPUB 不虚构固定页码，按内容单元回查。纯图片封面明确标注未提取图中文字；纯扫描、受保护、交互内容等边界见 [EPUB 处理说明](../skills/textferry/references/epub.md)。本轮未验证真实书籍，也不据自制样本声称所有 EPUB 均可转换。

## 首次使用

提问时先解释两档区别：基础转换提取内容并检查覆盖，适合搜索浏览，未经逐页校正；AI 整理校正对照来源检查正文、顺序、公式、注释和结构，保留底稿并另给整理稿及具体疑难，耗时更多。再确认 Markdown / Word，推荐 Markdown。已说明的选择不重复问。

材料检查在后台进行。费用构成、额度和共享库现状按需说明，不做固定开场讲解；没有共享索引不声称已经搜索所有书籍。原生 EPUB 和可直接提取的 PDF 跳过 OCR 密钥配置。

## 仍有边界

- 核心入口暂无直接页段 / 章节过滤参数；PDF 节选需保留来源对应，EPUB 手洗布局可选择范围。
- 基础档升级到整理档、快速切换输出格式仍需 Agent 协调，尚无统一的一步命令。
- Word 复杂公式可能使用图片；兼容方式设置仍不是任务内持久选项。
- 安装器保留已有目录，尚无正式的一键升级；本次本机更新按旧发行内容校验后同步，未覆盖其他文件或凭证。
- 默认公共共享库尚未启用；EPUB 与带图成果当前不进入目录。Windows / Linux 未获得与本机同等验证。
