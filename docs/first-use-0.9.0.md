# Pi / Flash 新用户实测 · 0.9.0

2026-10-28，三段实际 Pi 会话分别完成首次安装、首次转换和追加 Word。全部模型消息使用 `deepseek-flash`，共 5 条模拟用户输入。对话由当前 Agent 逐轮模拟用户回答；这不是真人新手试用，也不是一次无干预盲测。

## 过程

1. 只提供发布 ZIP，要求安装到隔离项目的共享 Skill 目录。安装及离线自检通过，Word 和 EPUB 组件未提前安装。
2. 重启 Pi 后，通过普通文件转换请求触发 Skill。启动元数据确认来源为自动发现、项目作用域，没有显式调用技能命令；其他用户级技能被测试设置排除。
3. Agent 先解释两档，用户选择 AI 整理校正，再询问格式并推荐 Markdown。用户明确整份、隐藏页码后才开始检查环境和凭证。
4. 两页自制扫描 PDF 使用已有环境变量令牌，真实百度 OCR 一个批次处理两页。Agent 查看来源页图，恢复表格、修正字母误识、保留两条原注，生成中文命名的三份成品。
5. 交付后按规则清理页图和上传副本。来源 PDF、机器全文、核查、映射和受理回执保留。
6. 修正首轮交付链接问题后，重启 Pi，请求追加 Word 并保留 Markdown。使用已保存文字导出，没有重新识别，最终回复采用程序提供的可点击链接。

## 本轮实际发现和修正

- 首轮虽然写“点击打开”，却把路径写成代码。改为由 `deliver` 生成 `delivery_message`，包含可直接采用的 Markdown 链接及实际整理范围，追加 Word 会话已采用。
- 一条带特殊符号的核查说明通过命令行传递失败，Agent 改写后成功。加入 `--note-file`，由 UTF-8 文件直接读取核查说明，并有包含公式、反引号和引文的回归检查。
- 一套预览环境缺少可用中文字体，渲染页出现缺字。Quick Look 显示中文正常；主会话另用本机 LibreOffice 渲染并查看，中文、表格及原注均完整。Word 说明补充了字体和内容缺失的区分。

## 文件大小

同一两页样本，0.8 任务目录文件大小合计 60,688,519 字节；0.9 在保留 Markdown 和 Word 后为 12,114,516 字节，约减少 80%。新结果有一份来源 PDF、零份缓存页图、一份远程受理回执。数字不包含运行环境、输入文件和测试安装包，不能当作运行内存或独占物理空间回收量。

默认 Markdown 整理档顶层是整理稿、机器底稿、整理说明。追加 Word 后增加一份 Word，其他记录收在隐藏工作目录。整体移动、核查后的重建和离线追加均另有程序回归；PDF / EPUB 两类独立执行另列在验证记录。

## 范围与限制

本轮使用两页自行编写的材料，包含简单等式、两列表格和两条无正文锚点的原注。AI 将简单等式处理为普通可编辑字符，Word 中这些不是原生公式对象；复杂公式机制有单独程序测试。本轮没有重新校对真实长书、古籍和复杂数学教材。

测试系统已有 Python、uv、缓存及本机办公预览工具，不能代替全新电脑的冷安装测试。其他 Agent 的真实对话、Windows / Linux、全部版式及固定耗时仍未逐一验证。完整工具与会话证据保留在本机私有试验目录，没有放入公共源码或发布包。
