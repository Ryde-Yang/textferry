# writing-for-agents 自检 · 0.9.0

日期：2026-10-28。依据 Matt Pocock 的 writing-for-agents 及 SKILL-MECHANICS。实测 0.8 中发现：已有规则仍被模型略过，首次引导前读了多份文档、提前安装 Word，并把 Word 当作默认推荐。因此本轮按观察到的行为调整信息层级，不能仅以“文档写过”认定体验通过。

| 原则 | 本轮修改 | 完成与边界 |
| --- | --- | --- |
| 步骤次序 | 主入口首句指向选择沟通；档位、格式分别等待回答，明确后进入安装 | 真实会话需验证，不以静态文字代替 |
| 用户选择 | 整理档将来源页码 / 章节标记的显示方式纳入开工前完成标准，导出显式传参 | 既有选择沿用；此前实测由用户主动给出隐藏页码，不作为主动询问已验证的证明 |
| 条件指针 | 兼容、环境、凭证均放在选择完成后的相应分支 | 只安装任务可直接进入环境分支 |
| 单一来源 | 档位解释以主文件为准；交付和缓存规则集中于 delivery.md | 首页面向人类仍保留简短产品解释 |
| 人类负担 | 用户决定档位、格式、范围；组件、缓存预览和清理由 Agent 完成 | 不新增缓存选择问卷 |
| 完成标准 | deliver 生成实际文件及可直接采用的链接回执，compact 先绑定证据再清理 | 未完成或核查陈旧会拒绝清理 |
| 正向指令 | 用 setup 的安全来源状态诊断，给可点击成品链接，用 status 汇报实际进度 | 密钥和防覆盖仍保留必要硬边界 |
| 环境事实 | 路径与文件名由命令返回，参考只解释用途和恢复语义 | 参数以 --help 为准 |
| 指令成本 | 常规任务使用公开入口和简短 status，无需阅读实现代码及诊断全文 | 异常从运行返回、help 和对应参考开始 |
| 宿主中立 | 使用文件、命令、图像与宿主异步能力，核心未绑定特定工具名 | 能否自动发现和显示进度仍取决于宿主 |

Flash 首轮仍把路径写成代码，故改为程序生成交付消息并明确原样使用；追加 Word 的新会话已采用真实 Markdown 链接。一次核查说明的字符传递失败促成 UTF-8 文件入口，减少命令行转义负担。

程序测试、源码包独立执行和 Flash 真实对话分别记录在 verification.md；本自检不替代它们。以下保留 0.8 自检历史。

# writing-for-agents 逐项自检 · 0.8.0

日期：2026-10-28。依据：Matt Pocock 的 [writing-for-agents](https://github.com/mattpocock/skills/tree/main/skills/productivity/writing-for-agents) 及其 `SKILL-MECHANICS.md`。本轮由当前 Agent 对已写文件逐项核对，记录发现、修正和边界；程序测试另列，不能替代这份指令自检。

## 核对结果

| 写作原则 | 核对内容 | 本轮结果 |
|---|---|---|
| 条件指针 | 能否判断何时读哪个参考文件 | 补强首次安装、更新、无 uv 和权限不明的读取条件；环境指针放在运行命令前 |
| 信息层级 | 公共步骤是否清楚，分支是否按需加载 | 主入口保留任务选择、执行、核查和交付；宿主适配、令牌、EPUB、Word、共享分别放在分支参考 |
| 人类负担 | 哪些决定必须由用户作，哪些由 Agent 完成 | 用户决定档位、格式、范围和公开意愿；环境、命令、内部记录由 Agent 处理，不把参数选择交给小白 |
| 完成标准 | 是否能明确区分完成、部分完成和未完成 | 补充基础 / 整理各自的交付产物及文件可访问标准；尚未完成的格式或检查明确列出，并说明恢复办法 |
| 共享触发 | 是否覆盖用户请求及完成后的自愿邀请 | 修正“只有用户先要求共享才读取规则”的窄条件；完成真实的纯文字 PDF 转换后，也可按规则判断是否适合邀请 |
| 单一规则来源 | 同一材料类型规则是否在多份文档重复维护 | 从核查记录文档移除论文、图书和古籍规则副本，统一指向材料 SOP；共享命令详情留在共享分支 |
| 规则与步骤同处 | 条件、动作、异常出口是否能一起读到 | 环境异常与恢复放在同一参考；AI 整理保留修订、疑难和导出条件；交付与追加需求相邻 |
| 正向表达 | 是否先说明应该产出和如何继续 | 主流程以保全、核对、记录、交付组织；保留防覆盖和公开同意等必要硬边界，并配可执行的下一步 |
| 稳定术语 | 是否用一个名称表达一个概念 | 用户侧统一“基础转换”“AI 整理校正”“机器底稿”“整理稿”；代码中的既有命令名称保留在执行说明 |
| 剪裁与时效 | 是否有过时信息、环境缓存和无效叮嘱 | 合并重复的 convert 命令行，删除通用入口中的 Codex 专属表述；状态和来源语义仍保留，参数细节以当前 --help 为准 |
| 调用方式 | 是否符合自然语言请求和 Agent Skills 格式 | 保留 name / description 与自动发现能力，不复制宿主专属的调用开关；可手工加载同一 SKILL.md |
| 宿主边界 | 是否把某个 Agent 的工具当成必需能力 | 核心使用文件和 Python 命令；展示元数据为可选，删除 OpenAI 展示文件仍可执行自检；明确图像校核与远程凭证要求 |

## 具体修正

1. 环境指针明确覆盖首次安装、更新、缺少 uv、环境异常，并位于命令执行之前。
2. 交付按基础档和整理档区分，避免要求基础档链接尚未生成的整理稿或整理说明。
3. 可选共享同时覆盖用户主动提出和完成真实转换后的邀请判断；未答复时预览保持本地。
4. 材料类型规则集中在 SOP，核查文档只负责四项检查及记录。
5. 核心说明、安装提示和令牌配置不再要求 Codex；费用说明改为当前 Agent 的模型 / 平台用量。
6. 宿主差异集中到兼容参考与安装器参数；Python 运行入口保持一致。

## 验证层次

- **本自检**验证文字如何引导 Agent 决定读取、执行、停止和交付。
- **程序回归**验证目录选择、配置、转换、恢复、核查和导出的机制，结果见 [验证记录](verification.md)。
- **独立目录执行**验证不依赖开发目录和可选的 OpenAI 展示元数据。
- **真实宿主体验**：Claude Code、Cursor、Gemini CLI 的真实对话和真人新手试用尚未逐一进行。跨宿主目录与执行层测试不等于这些体验已验收。

仍保留的重复主要是公共入口的必要约束与面向人类首页的产品解释。后续修改时继续按所属分支维护，避免新增多份详细规则副本。自检不以行数、测试数量或“零问题”作为结论。
