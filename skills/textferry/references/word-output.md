# Word 输出与公式检查

只在用户选择 Word 时执行。直接使用已完成的页稿或整理稿导出，不重新 OCR，也不重新整理正文。Markdown 与来源记录仍保留，方便回查公式源码。

先安装 `word` 可选依赖。普通文本、脚注、表格和简单公式使用原生 Word 对象。含复杂矩阵、多行推导或长公式的材料，应先验证代表页；原生呈现存在兼容问题时使用公式图片，保留简单行内公式可编辑。普通用户只需知道“复杂公式以清晰图片保留”；组件路径、数学命令等留在执行记录中。

图片方式保留原公式内容，按比例适应页面，不能截断矩阵、把未知项补成零或为缩短公式改写等式。保留公式源码用于修改。用户明确要求所有公式可编辑时，应说明实际兼容限制，不能把图片称为可编辑公式。

真实稿件导出后，先确认预览环境能够显示中文；缺字或方框时检查字体配置，或换用具有中文字体的本机渲染器，区分预览环境缺字与文档内容缺失。然后检查公式、矩阵行列、分行、页边、图片和脚注；自制样本通过不能代替真实材料验证。Markdown 的公式分隔符内侧不能保留多余空格，块公式分隔符独占一行，公式内部不留空白段落；程序规范排版空白，机器底稿和页级核查证据保持原样。

核查需要区分三件事：公式内容忠于源页、阅读器把内容识别为公式、实际页面呈现完整。统计公式节点数或 LaTeX 语法通过不能代替后两项检查；还要查正文中是否残留未识别的公式命令。

## 公式图片组件

Agent 优先使用执行环境已有的 Node.js、mathjax-full 和 sharp；组件缺失时安装到使用者缓存，不能把依赖或二进制塞入书稿或公共源码。锁定的组件清单位于 `assets/word-math/`。将清单复制到用户缓存中的专用目录，用其锁文件安装；已有目录先检查，不覆盖使用者自己的配置。Markdown 与无复杂公式的 Word 不要求这组组件。

执行兼容导出时设置：

- `TEXTFERRY_WORD_EQUATIONS=compatible`：显示公式及复杂行内公式使用图片，简单行内公式保留原生数学对象。
- `TEXTFERRY_NODE`：经探测可用的 Node.js 可执行文件。
- `NODE_PATH` 或 `TEXTFERRY_NODE_MODULES`：实际安装的 `node_modules` 目录，多个目录按操作系统路径分隔符连接。

图片和原式元数据保存在任务的 `word-math/`，Word 中嵌入图片并保留原式描述。按原式、渲染器版本和参数缓存；格式切换和再次导出可复用，不重新调用 OCR。元数据保留原公式，不能把图像当作可编辑数学对象。需要原生公式时可显式设置 `TEXTFERRY_WORD_EQUATIONS=native`，并在目标阅读软件中验证复杂公式。

追加格式使用 `change-output bundle --format word`；公式方式可加 `--equations native|compatible`，保存到任务，后续导出沿用。整理稿已被直接修改时先保留并对应回工作单元，再重导出。
