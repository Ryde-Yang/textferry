# 材料处理 SOP

适用范围：中文论文、现代图书、古籍 PDF、EPUB 的全文转换与手洗整理。手洗的任务是恢复材料已有的文字和结构；内容摘要、翻译和学术论证另行处理。

## 一、两份主产物与来源记录

| 产物 | 内容与用途 |
|---|---|
| `machine.md` | 按输入 PDF 逐页保存机器文字、页码、来源链接及失败占位，供搜索、对照和回查 |
| `handwashed.md` | 实际对照来源后整理的全文，恢复段落、引文、章节及注释；可显示或隐藏页码 |
| `handwashed.sources.json` | 手洗稿各页及注释的来源区间、底本指纹、选页范围、书目信息、核查记录和待核项 |

原始 PDF 是裁决底本。机器文字、搜索结果和其他版本用于发现问题，不能静默替换底本。机器底稿与初始识别保留；修订写入页级工作稿，完成后再导出手洗稿。`document.review.md` 是这些工作稿的自动汇总，不代表手洗已完成。

快速转换完成机器底稿；校核整理以两份主文本为目标。只做若干页、只恢复结构或仍有疑难时，交付相应阶段，并明确范围。完整输入 PDF 可能只是一本书的节选，不能据此宣布全书完成。

## 二、接手与诊断

1. 确认输入文件、输出位置、材料类型、处理范围和用户已有修订。新任务用空目录；已有任务先读报告和当前稿件，保留用户改动。
2. 运行 `inspect` 检查全部输入页。可靠文本层直接抽取；扫描页或劣质文本层用 OCR。抽取成功不证明阅读顺序正确。
3. 需要 OCR 时先完成 [配置引导](onboarding.md)，检查配置状态。失败、限流或排队暂停时保存进度，使用 `resume` 恢复；不反复提交相同页扩大费用。
4. 默认保留原文繁简、术语和措辞。用户明确选择时才作繁简转换，不借此重写引文或作者论证。公式、表格、链接和稀见字不能因难处理而删除。
5. 记录完整页槽、输入 PDF 副本及哈希。失败页不得用前后文猜补，更不能从成品中静默消失。

## 三、来源信息和页码

执行 `prepare-handwash`，按底本填写 `handwash/source.json`：题名、作者、年份、出版者、版本、处理范围、首引与再引格式。未知字段保留 null 并说明待核；文件名与 OCR 猜测不能当作已核书目。

`handwash/layout.json` 中每个选页对应三个不同概念：

- `pdf_page`：当前输入 PDF 中从 1 开始计数的物理页。
- `printed_page`：实际读到的书页标签，可为罗马数字、汉字或数字；未核实则 null。
- `original_pdf_page`：输入是截取件时，在截取前文件中的物理页；仅在确知映射时填写。

封面、前言、折页、缺页可能使页码偏移改变，不臆测全书统一偏移。隐藏页码只改变手洗稿的阅读显示，不移除来源映射。

## 四、图书先建立结构

对照目录与正文辨认前置材料、卷章、章序、附录、校勘和参考文献。按原书标题和编号组织，不按 OCR 局部块重新编号；目录、附录和书目本身也需要整理。

在 `handwash/structure.md` 记录本次涉及的卷章标题、来源页范围、首句和尾句，作为核对章界的工作记录。内容概述不能代替原文。

长书可以分三轮：建立结构与放入底稿、恢复可顺读全文、细核文字与注释。前两轮只说明完成了相应阶段。长章分批处理时，前后页接续、章首和章尾另行回查，不能在分页处丢掉长引文、章末注或续疏。

## 五、页级手洗的共同规则

以 `review/pages/NNNN.md` 为编辑区，实际查看同名页图；必要时放大或重新渲染，不能只比较两份机器文字。

- 保留作者完整正文、例证、限定语、判断强弱与论证顺序。禁止用摘要、白话解释或“重点引文”替换全文。
- 恢复段落和标题层级，连接被版面切开的句段。只清除已确认的重复页眉、假断行、扫描噪声；机器底稿保留这些原始证据。
- 区分作者正文、引用、作者注、古注、疏文及现代整理者校按。长引文可用 `>`；作者分析必须留在引文块外。
- 保留可识别的公式、表格和图片指向。图片包含必要内容时，可保存本地图片并在正文链接；不要只因转成 Markdown 就舍弃图表。
- 可由源页确认的误字应修复；疑字、残字和无法确认的归属应保留位置并记录待核，不凭常识或通行版本猜造。
- 保留用户已有的稳定标题、明确使用的块锚点及编号。来源路径用本任务目录内的相对路径，不要求专用双链插件。

## 六、按材料类型处理

### 论文

恢复题名、作者、摘要、关键词、分类信息和编号标题。保持作者论证完整，逐段区分作者陈述与引文；跨页续句应看相邻页后接回。

作者原注整理为标准 Markdown 脚注，如 `[^1]`，汇总到 `## 注释`。参考书目引用用另一套命名空间，如 `[^ref-1]`，汇总到 `## 参考文献`。两套引用都须按实际指向配对，不能因为数字相同就合并。圈号可作识别中间状态，最终编号应可稳定定位。

没有找到正文标记的页底文字保留并列为待核，不补造标记。仅凭程序配对通过，也不能证明注释内容归属正确。

### 古籍与注疏型图书

经文或原典正文加粗，解释文字不随之加粗；底本已有的章指、章旨、注家名和段落完整保留，不自撰章旨。

按底本辨认注、疏、正义、集注等层次，将解释放在所释文字附近。标签用于显出已有边界，不能发明原书没有的体系；也不能用一个笼统标签吞并多个解释层。出现“某氏曰”不必机械地另起引文块，要看它在底本中的位置和归属。

现代点校、版本异文、校勘记、整理者按语与连续经注疏区分。逐条检查锚点和所释文字；边栏卷次、双行夹注、章尾长疏和跨页续疏是重点。原书已经分置的校勘材料不要混入连续正文。

有可靠同系统版本时可互校并记录依据，不能静默拿他本覆盖底本。没有互校条件就说明未做。注疏、正义和集注可以采用不同页面模型，见 [材料整理示例](examples.md)。

### 现代研究图书

恢复原书卷章、节次、引文、脚注和书目，保留全部作者分析、例证和限定语；不能只选“重要段落”。长引文与作者分析分开，章节首尾、附录中的实质文字及参考文献都检查。跨章引用和脚注归属按书中实际关系整理。

### 含公式的教材

逐项对照数字、正负号、不等号、上下标、求和范围、矩阵元素和变换箭头。水印可能被误识为负号；字体粗细可能区分标量和向量。公式能渲染只证明语法可用，不能证明内容忠实。

整理时增删项、替换系数或重建公式，需回看清晰源图并在页级记录中写明位置和改动。收尾另作一轮公式改动复核，重点查漏项、重复粘贴及按数学关系自行纠错。声称“原书如此”或“原书有误”前，要放大核实该处；看不清就记疑难，不能把识别或整理错误归到原书。原页本身前后不一致时保留各处原文，说明差异，不静默统一。

## 七、跨页接续与注释汇总

`handwash/layout.json` 的 `pages` 是本次手洗范围，按输入 PDF 页升序排列。首个选页必须为 `separate`；后续页初始为 `unchecked`，实际判断后改为：

- `join`：延续上一页同一段或句；`joiner` 用空字符串接中文，或单空格接英文词组。
- `separate`：另段、另章或不连续选页；非连续输入页不能直接 join。

接续前检查段尾、段首、标点、标题及注释；不能一律去掉换行。表格、公式、列表或引文跨页时，先在页稿中恢复有效结构，再确定连接方式。页码显示沿用用户选择，将来源标记安排在结构边界；需要调整显示方案时先说明原因并确认。

标准脚注定义可暂留在相应页稿底部，导出时统一移到文末并记录定义所在源页。多段注释的续行缩进；全篇编号不能重复。重号、缺定义、无正文标记的定义会阻止导出，必须查明后处理，不能为通过检查而编造来源。

## 八、核查与导出

实际手洗并查看页图后，执行 `review-page` 登记具体修正、核查者和疑难：

| 项目 | 核查内容 |
|---|---|
| body | 正文、引文、注释文字是否漏失、误识、重复或被改写 |
| order | 栏序、竖排方向、注释位置及跨页阅读顺序 |
| notes | 正文标记与脚注、尾注、注疏及校勘的归属与配对 |
| structure | 标题、卷章、经注疏、引文与分析的层次 |

只核一项就记录一项；四项做过仍有疑难，用 `--issue` 如实登记。之后修改页稿、机器文字或页图会使相关旧记录失效。

完成所选页后通读全文，复核章界、跨页接续和两套注释编号，执行：

```bash
uv run --project "$SKILL_DIR" python "$SKILL_DIR/scripts/run.py" export-handwash "/path/bundle" --page-numbers hide --reviewer Agent --note "实际检查的章节首尾、跨页连续性与注释配对情况。"
```

`hide` 隐藏来源标记，`show` 显示 PDF 页码及已填写的书页标签（EPUB 为来源章节）；两者均保留来源映射。交互按主入口在开工前取得用户选择，导出时显式传参；底层命令的默认值不能代替用户决定。仍有内容疑难时先继续核查；需要阶段交付时可用 `--allow-unresolved`，《整理说明》直接列出具体问题。该参数不能绕过注释格式错误。

不要直接编辑自动汇总稿。成稿有新改动时，先保存并回写页稿、复核涉及页、重新导出；程序不会静默覆盖被直接修改过的成稿或来源映射。

## 九、质量标准与收尾

“已转换”“可顺读”“已手洗”和“准出”是不同状态。转换成功不能升级为已手洗，抽检几页不能升级为全书准出。`handwashed` 只说明所选页具备当前核查记录、明确边界及通过格式检查的成稿；程序不授予学术准出。

交付前按 [质量标准](quality.md) 对应材料自审，尤其检查章尾缺漏、作者词气、引文边界、经文粗体、注疏归属、两套脚注和来源映射。细核、概览、未核、待核分别报告。

最低收尾动作：

1. 确认源 PDF → 机器底稿 → 手洗页稿 → 成稿与映射的来源链可查。
2. 回看改动涉及的源页，检查漏文、改写、错层及引用错配。
3. 检查成稿阅读效果及修改范围，保留用户原有内容。
4. 运行 `report` 与 `handwash-status`，确认当前状态和实际覆盖。
5. 向用户交付两份主文本、页码显示方式、来源映射及剩余问题；没完成手洗则明确阶段。

交付格式按用户选择：Markdown 为默认推荐，Word 为可选。Word 保留标题、粗体、表格与脚注；普通公式可编辑，复杂公式可用清晰图片，按 [Word 输出](word-output.md) 验证并说明。正文不显示处理状态或机器记录文件名，疑难另写《整理说明》。

公开贡献另按 [共享规则](sharing.md) 执行，不能把用户本地整理许可理解成自动公开授权。

EPUB 按章节对照与保全图片，适用本 SOP 的忠实性、注释、结构和疑难规则；分页相关规则按 [EPUB 处理](epub.md) 换成章节定位，不虚构页码。
