# 环境准备与恢复

跨宿主安装方式见 [Agent 兼容](agent-compatibility.md)。安装器从项目根目录执行，默认准备运行环境并调用 `doctor`。只有离线自制样本通过才返回 `ready`；`--no-setup` 仅复制文件，返回 `copied`，两者区别明确。

## 准备运行环境

Agent 使用 Skill 绝对路径。存在 `uv` 时：

```bash
uv run --project "$SKILL_DIR" python "$SKILL_DIR/scripts/run.py" doctor
```

需要 EPUB / Word 时分别加 `--extra epub` / `--extra word`。没有 `uv` 时，用 Python 3.10+ 在 Skill 目录建立 `.venv`，以其中的 Python 安装 Skill 目录；按任务选择安装 `"$SKILL_DIR[epub]"` 或 `"$SKILL_DIR[word]"`，再运行 `scripts/run.py doctor`。使用虚拟环境中的 Python，不依赖工作目录和全局包。

环境安装失败时保留已经复制的文件，说明“环境尚未准备完成”；修复网络、Python 或依赖后可重复运行安装。OCR 令牌在确实需要扫描识别时配置，不能用填写令牌解决依赖安装问题。

## 更新

`install.py --update` 在改写前将旧文件副本存入用户缓存中的 `textferry/install-backups/`，避免旧 Skill 被再次发现。未在安装清单内的其他文件保持原位，凭证在独立的本机配置目录中。若用户自改过 Skill 指令，检查备份并合并其规则，再完成更新验收。

更新后执行 `doctor`，确认当前版本的入口和模型配置均来自安装目录。默认不携带开发环境、虚拟环境、凭证或材料缓存。

## 出错后的下一步

- **等待识别服务 / 队列满**：报告已经保存的范围及等待原因，本轮最多一次恢复；已有受理编号继续查询原任务。
- **提交是否受理不明确**：先核对服务端任务，再决定后续；保留本地回执，避免重复识别。
- **EPUB 中断**：`resume` 在本机继续待处理章节，保留已完成文字和已有工作稿，不要求百度令牌。
- **输出目录已有内容**：已有任务用 `resume`，新材料用新目录。
- **文件被用户直接修改**：保留该版本。基础稿显式追加 Word 可使用当前修订；升级整理需先把修订对应到来源。整理稿需回写工作单元、复核后导出。
- **格式组件缺失**：补装对应组件，然后在原任务追加格式或恢复；不重新 OCR。

程序提供提取、等待识别、取回结果和 Word 导出事件。进度用这些事实说明，不凭运行时长宣称完成；当前尚不能预报全书整理的固定耗时。
