# 首次使用的沟通方式

档位区别、提问顺序和默认值以主文件第 1 步为准。首条转换回复先帮助用户选择；安装和工具准备放在选项明确之后。只要求安装时先安装、自检，随后等待材料。

## 对话节奏

每轮只补当前缺少的选择。用户已给出档位、格式、范围或来源标记显示方式时直接沿用。格式选择明确推荐 Markdown；用户想阅读、编辑，并不等于已选择 Word。

整理档在格式、范围明确后，开工前补问来源标记。PDF 可这样问：“整理稿要显示来源页码吗？显示便于定位和回查，不显示便于连续阅读；两种都会保留来源对应关系。”EPUB 改问是否显示来源章节标记。用户只说“Markdown，整份都做”还没有回答这一项；不要代选隐藏，也不必再问已经明确的格式和范围。

输入较长时说明原文件物理页与印刷页的区别；EPUB 先按章名核对。检查和组件安装由 Agent 完成，用户无需学习命令。

## 进度

开始准备、识别、校正或导出前，先用一句话说明当前阶段。运行时保留进度输出，不用只保留最后几行的方式遮住等待原因。

宿主支持异步或后台任务时，让长命令及时返回，保存输出；用 `status` 的简短结果和程序进度判断当前情况。等待期间有新阶段或完成数时更新，超过一分钟仍等待时说明实际等待原因，避免让用户以为停住。工具无法异步时，在长调用前说明将等待哪个结果，返回后立即更新。

例：“识别任务已受理，正在等服务返回。”“两页文字已取回，接下来对照检查公式和表格。”阶段和数字必须来自实际结果。中断时说清已保留的内容和继续方式。

## 配置与收尾

扫描识别才检查令牌。用 `setup` 的安全诊断结果引导，流程见 [令牌配置](onboarding.md)。看到未配置时只描述当前执行环境的状态；保存成功和调用成功分别说明。

完成后按 [成品与缓存](delivery.md) 给中文命名的成稿链接。疑难直接说清位置与内容；已达到范围后交付，避免因单个疑字无限扩展任务。内部 JSON、状态码和核查字段供恢复使用，普通交付无需列成文件清单。

## 按需解释

费用、额度不足或用户询问成本时，说明识别服务与 Agent 所用模型 / 平台用量分别计算，以各账号页面为准。共享索引及实际收录范围在用户请求复用或贡献时说明。
