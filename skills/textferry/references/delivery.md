# 成品与缓存

新任务的目录：

```text
书名/
  整理稿.md              # 或用户选择的 .docx，两种都要才双份
  机器底稿.md
  整理说明.md
  .textferry/       # 来源、插图、页稿、核查与恢复记录
```

以上是 AI 整理档。基础档 Markdown 直接使用机器底稿，不再复制同内容文件；选择 Word 时另给基础稿.docx。`deliver` 对旧式任务默认生成 `成品/` 子目录，已有任务无需迁移。

## 生成交付

1. 先完成本次转换和所选核查。选择 Word 时按 [Word 输出](word-output.md) 验证实际页面。
2. `deliver BUNDLE` 生成成品，`files` 为绝对路径，`delivery_message` 是直接用于回复的 Markdown。中文文件名便于阅读；来源、插图和原注图片链接会对应工作目录。
3. 原样使用 `delivery_message`，保持其中已经生成的 Markdown 可点击链接格式。另用一小段补充实际疑难或重要处理选择，详细工作记录在用户询问或出错时解释。
4. 用户保留、移动整个成果文件夹，来源及插图链接才完整。单独复制一个 Markdown 只带走文字；`Word` 的正文图片已嵌入文档。

生成的交付稿与内部页稿分别保留。用户改过交付稿时，`deliver` 和追加格式会停止并保留修改。Agent 沿用用户已明确的修订要求，将改动对应回页稿并复核、导出内部整理稿；把用户改过的交付原件移到独立的“用户修订备份”位置，再运行 `deliver` 在空出的路径生成新稿。保留原件和原有导出记录，不以删标记绕过保护。用户尚未明确采用哪版时才询问。

## 完成后清理

`compact BUNDLE` 只预览候选文件和逻辑字节数；Agent 核对候选属于已完成任务的派生缓存后，用 `compact BUNDLE --apply` 清理，无需让用户选择缓存细项；用户要求保留时沿用其选择。程序只接受转换已完成、整理稿与当前核查一致的任务。正文资产、文本、来源映射、核查记录和远程受理回执都保留。

- 新 PDF 选页任务仅保留必要的摘页 PDF 和原页号映射。整本来源只有用户要求时加 `--keep-original`；旧任务承诺保留的整本来源继续保留。
- 已完成任务的分批及上传 PDF、可重建页图可以清理。原页图的核查哈希和来源绑定先写入缓存记录，清理后仍可检查当前版本；需要再看时用 `page-image BUNDLE --page N` 恢复。
- 正文插图和复杂公式图片是材料内容，留在工作目录内，不能当作页图缓存删除。
- 原生 EPUB 保留原书、章节和正文资产；当前没有 PDF 派生缓存可清理。

清理后追加 Word 或升级仍使用已有文字。继续任务时使用原成果文件夹或其 `.textferry` 目录；命令会定位内部任务。工作目录提供回查和恢复能力，交付时提醒保留整个成果文件夹即可。
