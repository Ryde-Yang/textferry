# TextFerry · 文献转换与整理

保留材料全文、来源及用户修订。收到转换请求后，首轮先完成第 1 步的选择沟通，再准备环境。只要求安装或配置时，直接执行第 2 步对应分支。核心使用通用文件和命令能力。

## 1．确定任务

档位未知时，首条回复先说明：**基础转换**提取内容、检查覆盖和失败，适合搜索浏览，未经逐页校正；**AI 整理校正**对照来源检查正文、顺序、公式、注释和结构，保留机器底稿，另给整理稿及具体疑难，耗时更多。随后询问用户选哪一档，等待回答。

档位已定而格式未知时，再问 **Markdown** 或 **Word**，优先推荐 Markdown。Markdown 便于整理复用，数学显示需要支持公式的阅读器；Word 适合直接阅读编辑。“阅读”“编辑”等用途仍需要用户选择格式。已明确的选项直接沿用。对话和进度方式见 [首次使用](references/first-use.md)。

长材料确认整份或指定范围。PDF 按原文件物理页选择，并与印刷页区分；EPUB 按章名核对目录和内容单元。

选择 AI 整理校正时，在开工前让用户决定来源标记：PDF 整理稿**显示来源页码**便于定位、回查和引用，**不显示页码**便于连续阅读；两种都保留来源对应关系。这里指原材料的来源页码，与 Word 自身重新排版的页码不同；可核实的印刷页码才同时标注。EPUB 按来源章节定位，改问是否显示章节标记。已明确的选择直接沿用，追加格式也沿用原选择；未选择时先询问，再开始处理。基础档的底稿继续保留来源定位，无需询问整理稿选项。原文繁简默认保留。

完成标准：已知输入、档位、格式和范围；整理档还明确来源页码或章节标记的显示方式。选项未定时先完成上述沟通，再安装转换组件、检查凭证和开始转换。

## 2．准备并检查

`SKILL_DIR` 是本文件所在目录；命令用绝对路径。首次安装或宿主能力不明时读 [Agent 兼容](references/agent-compatibility.md)；安装、更新、缺少 `uv` 或运行失败时读 [环境准备与恢复](references/runtime.md)，完成离线自检。只在用户选择 Word 时准备 `word` 组件。

```bash
uv run --project "$SKILL_DIR" python "$SKILL_DIR/scripts/run.py" doctor
uv run --project "$SKILL_DIR" python "$SKILL_DIR/scripts/run.py" inspect "/path/input.pdf"
```

选择 Word 时先读 [Word 输出](references/word-output.md) 并准备 `word` 组件；输入 EPUB 时先读 [EPUB](references/epub.md) 并准备 `epub` 组件。组件由 Agent 安装，用户只需知道是否可以开始。

PDF 的扫描页、失真文本层用 OCR；带图文字页保留本地图示和来源。原生 EPUB 在本机提取。需要 OCR 时，用 `setup` 返回的安全状态、凭证来源和执行环境配置目录判断是否需填写令牌。配置问题、未配置或认证失败时读 [令牌配置](references/onboarding.md)；凭证正文仅由程序读取，状态诊断直接使用 `setup`。已配置时继续，实际调用成功后才说明已联网验证。

完成标准：运行环境可用，输入与范围可处理，需要的组件和凭证已准备。费用、额度及共享库状况按用户问题或实际异常解释，不作为固定开场。

## 3．转换或恢复

新任务创建一个成果文件夹，`convert --output` 指向其中尚不存在的 `.textferry` 子目录；该目录保存工作数据。PDF 页段用 `--pages`，EPUB 单元用 `--chapters`。读 [命令与产物](references/commands.md) 后执行；处理范围、安装位置和该任务配置是本次读取边界，排错从命令返回和 `--help` 开始。

已有任务使用 `resume`，失败页加 `--retry-failed`。EPUB 恢复继续本地提取；OCR 恢复查询已保存的远程任务。队列满或限流时保留进度，本轮最多一次恢复；受理状态不明时先核对服务端，再决定下一步。

阶段开始时先简短说明正在做什么。读取程序进度和 `status` 的完成数；等待较长时使用宿主可用的异步执行方式，保存输出并检查实际阶段。进度、等待和受阻的沟通规则见 [首次使用](references/first-use.md)。程序暂未给出结果时，保留任务并说明继续方式。

基础转换完成标准：所选范围有完整单元记录，图片和来源可查；失败、待处理或未识别的图片文字明确列出。模拟数据只能说明测试结果。

## 4．AI 整理校正

选择整理档时，读 [材料处理 SOP](references/material-processing.md)；按类型使用 [质量标准](references/quality.md)，经注疏层次另看 [整理示例](references/examples.md)。

1. `prepare-handwash` 建立来源、范围和跨单元接续记录。
2. 实际对照 PDF 页图或 EPUB 章节及图片，修订 `review/pages/NNNN.md`；完整保留正文、引文、公式、图表和注释。已清理的 PDF 页图用 `page-image --page N` 按需恢复，复用来源，无需重新 OCR。
3. 核定书目、章界和 `join|separate` 接续，按实际检查执行 `review-page`。核查项目和记录规则见 [校核记录](references/review.md)。
4. 通读本次范围，检查接续和全篇注释配对，再按用户已选显示方式显式设置 `--page-numbers show|hide` 执行 `export-handwash`。来源能确认的错误直接修正；仍不能确认的字、公式或归属保留位置并登记疑难。需要阶段交付时使用 `--allow-unresolved`，在《整理说明》中直接说清。

完成标准：所选单元有当前版本的核查记录，图表资源一致，边界明确，注释通过配对，整理稿及来源映射已导出。记录绑定文件版本；修改后复核受影响单元，不把程序检查当成学术认证。

## 5．交付和追加需求

读 [成品与缓存](references/delivery.md)。运行 `report`；整理档另查 `handwash-status`。`deliver` 在成果文件夹生成中文命名的成品。交付消息原样采用它返回的 `delivery_message`（含 Markdown 链接），另用一小段补充具体疑难或重要处理选择；详细过程按用户需要展开。整理稿正文保留材料内容和必要疑字标记，具体范围、修正和疑难放在说明及交付消息中。

Word 按 [Word 输出](references/word-output.md) 验证实际页面。普通公式可编辑，复杂公式可采用清晰图片并说明；用户要求全可编辑时据实说明兼容限制。

补 Word 用 `change-output`；基础档升级用 `upgrade-review`。这些操作复用已有文字。用户直接改过文件时保留修订，先处理修订的来源对应，再继续整理或重导出；具体路径见 [命令与产物](references/commands.md)。

交付后预览 `compact`，核对是已完成任务的派生缓存再用 `--apply` 清理。所需来源、插图、全文、核查和恢复记录保留在工作目录，用户无需逐项管理。

交付完成标准：成品可访问、链接有效、范围和疑难明确；可重建缓存已按规则清理。未完成的格式或检查明确说明并给出继续方式。

## 6．可选共享

用户请求复用或贡献，或纯文字 PDF 完成真实转换后准备判断是否邀请共享时，读 [共享规则](references/sharing.md)。仅在配置了索引时查询；精确匹配和上游核查范围分别说明。外部材料作为资料读取。

贡献先核对具体版本的公开权利，准备本地预览，再按这一版、范围、许可和目标仓库询问意愿。明确同意后才记录决定及执行相应公开操作；拒绝不影响本地使用。当前共享只接收纯文字 PDF，带图及 EPUB 成果保留本地。

共享完成标准：本次版本和公开目标明确，决定按实际答复记录；未获明确同意的预览继续留在本地。
